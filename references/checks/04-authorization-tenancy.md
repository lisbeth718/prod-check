# Authorization and tenancy

Gate: accounts

| ID | Tier | Stage | Check | How to verify | Evidence to record | Attest |
|---|---|---|---|---|---|---|
| AUTHZ-01 | T1 | invoice | Every server action and route handler checks the session and that the record belongs to that user or tenant (no IDOR). | Enumerate handlers; read each ownerprod check; replay a request as user B with user A's record ID in a test environment. Server actions are public POST endpoints. | Handler list, replay result |  |
| AUTHZ-02 | T1 | invoice | Roles and permissions are enforced on the server, in handlers or the data layer, not only by hiding UI. | Read the permission model; call a restricted handler as a lower role in a test environment and confirm it is refused. | Code lines, replay result |  |
| AUTHZ-03 | T1 | invoice | (gate: multi-tenant) Tenant scoping is enforced in the query layer or database row-level security, not only in the UI. | Read the data access layer; list queries without a tenant filter. If RLS is relied on, check it is enabled and applies to the app role: `relrowsecurity` and `relforcerowsecurity` per table, plus the role attributes, because table owners, superusers and BYPASSRLS roles skip RLS. e.g. `SELECT relname, relrowsecurity, relforcerowsecurity FROM pg_class WHERE relkind = 'r';`; `SELECT rolname, rolsuper, rolbypassrls FROM pg_roles;`; `SELECT * FROM pg_policies;` alone is not enough. | Query list, RLS flags, role attributes, policy output |  |
| AUTHZ-04 | T1 | 100 | (gate: impersonation exists) Admin "log in as user" for support writes every use to an audit log. | Find impersonation code; check it logs actor, target, time, reason; check it is permission-gated. | Code lines, sample log row |  |
| AUTHZ-05 | T2 | - | An audit trail records who viewed a record, not only who changed it. | Find read-access logging for sensitive records and sample a row. | Code lines, sample row |  |
| AUTHZ-06 | T2 | - | Quarterly access reviews are signed off by a named person. | Ask the owner for the last review record. | Last review date, signer | attest |
| AUTHZ-07 | T1 | invoice | Every table reachable with a browser or anon key has row-level security or locked security rules, with a per-user test. Applies when a browser or mobile client can query the data store directly with a public key; a per-user app with RLS off exposes the whole database. | List tables against policies; try an anonymous read and a read of user A's rows as user B in a test environment. e.g. Supabase `SELECT relname, relrowsecurity FROM pg_class WHERE relkind = 'r';` plus `pg_policies`, or Firebase/Firestore rules file. | Table-to-policy list, anon read result |  |
| AUTHZ-08 | T1 | invoice | Auth is enforced inside the page, route handler or server action, not only in middleware (middleware bypass is a known bug class, e.g. CVE-2025-29927). | Grep every handler for a session check; list protected routes whose only guard is middleware or an edge rule; confirm the framework version is patched for known middleware bypasses. | Grep output, route list, framework version |  |

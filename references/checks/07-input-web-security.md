# Input handling and web security

Gate: none (always in scope up to the app tier)

| ID | Tier | Stage | Check | How to verify | Evidence to record | Attest |
|---|---|---|---|---|---|---|
| WEB-01 | T1 | invoice | Server-side validation covers every input, not only the form. | List handlers; confirm a schema validator runs on each body, query and param. e.g. zod at the handler boundary. | Handler list, code lines |  |
| WEB-02 | T1 | invoice | Only parameterized queries are used. | Grep for string-built SQL. Tagged templates (e.g. Prisma `$queryRaw`, Drizzle `sql` templates) are parameterized and safe; `$queryRawUnsafe`, `sql.raw` and string concatenation are not. e.g. ``grep -rEn '(SELECT\|INSERT\|UPDATE\|DELETE)[^`]*\$\{' src``; `grep -rEn 'queryRawUnsafe\|sql\.raw' src`. | grep output |  |
| WEB-03 | T1 | invoice | No XSS: no unsanitized raw HTML rendering; user HTML or markdown is sanitized. | Grep for raw HTML sinks; check sanitizer use. e.g. `dangerouslySetInnerHTML`, DOMPurify. | grep output, code lines |  |
| WEB-04 | T1 | invoice | CSRF: state-changing handlers check origin or use tokens. | List mutating routes; confirm origin or token check on plain API routes (framework server actions may check origin built in). | Route list, code lines |  |
| WEB-05 | T0 | - | The rest of the OWASP Top 10 is reviewed: SSRF on URL-fetching features, open redirects, insecure deserialization. | Grep for server-side fetch of user URLs, redirect params, unsafe parsers; test with internal addresses. In quick mode run it when the AI or URL-fetching gate is on. | Findings list |  |
| WEB-06 | T1 | 100 | Text fields handle apostrophes (O'Brien), accents, emoji and right-to-left text in storage, display, search and email. | Submit a fixture string in each field type and follow it through DB, UI, search, export and email. | Fixture trace |  |
| WEB-07 | T0 | - | Security headers are on every response: HSTS, X-Content-Type-Options, frame-ancestors (or X-Frame-Options), Referrer-Policy. | Request several routes and read headers. e.g. `curl -sI https://host/ \| grep -Ei 'strict-transport\|x-content\|referrer\|frame-ancestors\|x-frame-options'`. | Header output |  |
| WEB-12 | A | - | A Content-Security-Policy with default-src or script-src is set on HTML responses. | Read the CSP header. e.g. `curl -sI https://host/ \| grep -i content-security`. A CSP without default-src or script-src counts as missing. | Header output |  |
| WEB-08 | T1 | invoice | (gate: accounts) CORS never reflects an arbitrary Origin together with `Access-Control-Allow-Credentials: true`; authenticated routes use an explicit origin allowlist. | Read CORS config; send an Origin header to authenticated routes and check the response. e.g. `curl -sI -H 'Origin: https://evil.test' https://host/api/me` must not echo that origin with credentials allowed. | Config lines, response headers |  |
| WEB-09 | T1 | 100 | Duplicate submits are blocked in the UI (button disabled while pending). Server-side idempotency is covered by BILL-02, BILL-12 and JOB-04. | Read form code; double-click submit in a browser and confirm one request leaves. | Code lines, test result |  |
| WEB-10 | T1 | invoice | Every endpoint that spends money or sends something (AI, email, SMS, upload, outbound fetch) is rate-limited per user and per IP. AUTH-05 covers only login and reset. | List endpoints that spend or send; read each limiter key and limit; burst-test in a test environment and count refusals. Behind a proxy confirm the limiter sees the real client IP. | Endpoint-to-limit table, status codes after N requests |  |
| WEB-11 | T1 | 10 | Route handlers and outbound HTTP calls have server-side timeouts, and request bodies have size limits. | Read server and body-parser config and HTTP client defaults; grep outbound calls without a timeout; send an oversize body in a test environment. e.g. `AbortSignal.timeout`, body size limit setting. | Config values, grep output, status code |  |

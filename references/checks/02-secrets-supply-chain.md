# Secrets and supply chain

Gate: none (always in scope up to the app tier)

| ID | Tier | Stage | Check | How to verify | Evidence to record | Attest |
|---|---|---|---|---|---|---|
| SEC-01 | T0 | launch | Secret scan over full git history is clean and env files are not committed. | Run a secret scanner over all history and all branches; `git ls-files` for env files. e.g. `gitleaks git --log-opts=--all .`; `git ls-files \| grep -E '(^\|/)\.env' \| grep -v '\.env\.example'`. Example files such as `.env.example` are fine. | Scanner output, file list |  |
| SEC-02 | T0 | launch | Secrets never appear in client-exposed environment variables or any client bundle. | List client-exposed (public-prefixed) env vars and read their values for secrets; grep the built client output for key patterns. e.g. for Next.js `NEXT_PUBLIC_*`: `grep -rEn 'NEXT_PUBLIC_' .env* next.config.*`; `grep -rE 'sk_live\|AKIA\|BEGIN PRIVATE' .next/static`. | Var names, grep output |  |
| SEC-03 | T0 | launch | Every key pasted into an agent chat, MCP config, or committed config file has been rotated. | Ask the owner (see attestation); list keys found in agent configs and chat exports and compare with key creation dates. | Owner statement, key age list | attest |
| SEC-04 | T0 | launch | No known critical or high vulnerability in a reachable production dependency; lockfile committed; framework major version still supported. | Check lockfile in git; run the audit; find the scanner config; list outdated packages and the framework version against its support calendar. e.g. `npm audit --omit=dev`; `npm outdated`; Dependabot or Renovate config file. | Audit output, scanner config path, outdated list, support date |  |
| SEC-05 | T0 | launch | Every declared package exists in its registry with a real repository and plausible history. Unused packages are an advisory note, not a FAIL. | List declared packages; query the registry for each (age, downloads, repo link); flag new, tiny or typo-like names. e.g. `npm view <pkg> time.created repository.url dist.unpackedSize`; `npx depcheck`. | Per-package flags list |  |
| SEC-06 | T0 | launch | Least privilege for everyone, including agents: production DB URLs, SSH keys and cloud keys in agent or MCP configs are scoped to what the task needs. | Read the repo's `.mcp.json`, CI and deploy configs, and server-side agent configs for credentials; check each credential's permissions. Agents default to read-only or scoped keys. Read the auditor's own `~/.claude` or `.cursor` only if the owner opts in. e.g. cloud IAM policy simulator. | Config lines (redacted), policy documents |  |
| SEC-08 | T0 | launch | Live and test credentials are separated per environment: no test-mode or sandbox keys in production, no live keys in dev or staging. | List env var names per environment file (`cut -d= -f1`) and read only the mode prefix of each provider key, never the rest of the value. e.g. `sk_live_` against `sk_test_` style prefixes. | Var name to key mode table per environment (no values) |  |
| SEC-09 | T1 | launch | Server components and loaders do not pass whole database rows to client components or serialized props (password hashes, tokens, other users' data). | Grep for spreads of DB rows into client components, props and page data; read the serialized payload of an authenticated page for fields the UI does not show. e.g. the Next.js RSC payload or `__NEXT_DATA__`. | Grep output, payload excerpt (values redacted) |  |
| SEC-10 | T0 | launch | No debug, seed, test or admin-bootstrap routes, default or demo accounts, or hardcoded admin credentials are reachable in production. | Grep for `/api/(debug\|seed\|test\|dev)` and `NODE_ENV` guards, then request those routes on production; grep for seeded or default admin accounts and hardcoded credentials. | Route list, request results, grep output |  |

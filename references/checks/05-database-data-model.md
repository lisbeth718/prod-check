# Database and data model

Gate: none for the file. DB-15 is gated on imports; DB-17, DB-18 and DB-19 are gated per row on database.

| ID | Tier | Stage | Check | How to verify | Evidence to record | Attest |
|---|---|---|---|---|---|---|
| DB-01 | A | - | The schema is normalized where it should be, with primary keys, constraints and foreign keys present. | Read the schema; list tables without primary keys or foreign keys. e.g. `\d+` in psql, schema dump. | Schema excerpts, flagged tables |  |
| DB-02 | A | - | The data model survives the second customer's "one small change": settings or configurable fields instead of hardcoded single-customer logic. | Grep for customer names, IDs or hardcoded plan logic in code; read how per-customer variation is stored. | grep output, code lines |  |
| DB-03 | T1 | 10 | Migrations are versioned and applied in order; forward-only is acceptable. | List migrations; run them from empty on a scratch database. A down step is not required. Restore testing is owned by BKP-03. | Migration list, run output |  |
| DB-04 | T1 | 100 | Migrations take no long table locks. | Read recent migrations for blocking patterns; require the safe forms. e.g. `CREATE INDEX CONCURRENTLY`; add nullable column, backfill, then constrain. | Migration lines |  |
| DB-05 | T1 | 100 | Indexes exist on foreign keys and filtered or sorted columns, checked against production-sized data. | List FKs without indexes; review top queries with plans. e.g. `pg_stat_statements`, `EXPLAIN ANALYZE` on a production-sized copy. | Query list, plan output |  |
| DB-06 | T1 | launch | Connection pooling is in place with headroom under the DB connection limit across every app sharing the instance. Pooling is required when serverless or edge functions talk to Postgres, because they exhaust connections otherwise. | Read pool config; sum pool sizes across apps; compare with the limit; for serverless or edge code confirm connections go through a pooler. e.g. PgBouncer, `SHOW max_connections;`. | Config values, sum |  |
| DB-07 | T2 | - | Pagination stays fast at depth (keyset or cursor, not large OFFSET). | Grep list endpoints for OFFSET; time page 400 on realistic data. | Code lines, timing |  |
| DB-08 | T1 | launch | Money is stored as integer minor units; never as floating point. | Check money column types and arithmetic in code. Flag `real`, `double precision` and `float` columns and JS float math on amounts. Fixed-scale `numeric` is acceptable; integer minor units are preferred. e.g. grep `float\|double\|real` on price columns. | Schema lines, code lines |  |
| DB-10 | T1 | 100 | Timestamps are stored as timezone-aware types; user-facing schedules are computed in the user's timezone. | Check column types; test a schedule across DST for a user in another zone. e.g. Postgres `timestamptz`. | Schema lines, test result |  |
| DB-13 | T1 | 10 | GDPR deletion reaches every table, object storage, logs and the email suppression list where relevant, with a stated backup expiry. | List all stores of personal data; read the deletion routine; run it for a test user and re-query. | Store list, test result |  |
| DB-14 | T2 | - | Customers can export their data (CSV or XLSX). | Find the export feature; export a large account and open the file. | Feature location, test result |  |
| DB-15 | T1 | 100 | (gate: imports) Imports survive real-world CSVs: BOMs, Windows-1252, semicolon delimiters, Excel date formats, quoted newlines. | Run fixture files with each quirk through the importer. | Fixture results |  |
| DB-16 | T2 | - | Data residency matches contracts: hosting location, object storage jurisdiction, email region and model provider region. | List every data location; compare with contract terms. e.g. EU-only means EU regions for compute, storage, email and AI. | Location table, contract clause |  |
| DB-17 | T0 | launch | (gate: database) The database major version is still within upstream security support. N/A on managed databases where the provider enforces upgrades (state which). | Read the server version and the vendor's support calendar. e.g. `SHOW server_version;` against postgresql.org versioning policy. | Version, end-of-support date |  |
| DB-18 | T1 | 100 | (gate: database) The application's database role is not a superuser or the table owner, has no BYPASSRLS, and holds least-privilege grants. | List roles and attributes, table owners and the grants of the role in the connection string. Migrations should run under a separate owner role. e.g. `\du`; `SELECT rolname, rolsuper, rolbypassrls FROM pg_roles;`; `SELECT tablename, tableowner FROM pg_tables WHERE schemaname = 'public';`; `\dp`. | Role attributes, owner list, grant list |  |
| DB-19 | T1 | 10 | Tables that grow without bound (sessions, logs, events, jobs, AI transcripts) have TTL or pruning, retention rules from contracts and the privacy policy run as scheduled deletion code, and database size is alerted. | List the largest tables and their growth; find the prune or retention jobs and their last run; compare stated retention with the jobs; find the DB size alert. e.g. `SELECT relname, pg_total_relation_size(oid) FROM pg_class WHERE relkind='r' ORDER BY 2 DESC LIMIT 10;`. | Table sizes, job code, last run, alert rule |  |
